# Failure and correction ledger

Initial entry · 23 November 2026. This record retains the defects that motivated remediation. “Rechecked” means bounded evidence for the specified path, with no claim about untested interleavings or hardware.

| Finding | Original evidence and impact | Response and remaining limit |
|---|---|---|
| DML-A01 · Schedule drift | Depth-2 cycle weights loaded into depth-3 sequence and changed logits by 0.177509. A same-shape baseline could also load recurrent weights. An absent checkpoint could silently restart a run. | Save and verify graph signatures. Fail closed on resume validation and missing/stale indexes. Rechecked with refusal tests. |
| DML-A02 · Malformed KV history | Different slot lengths silently changed logits by 0.00435843 in the audit. Empty lists gave an IndexError; mixed holes could be accepted. | Validate lengths, shapes, count, dtype/device and native cache provenance. Rechecked valid decode and malformed entries. Plain lists still lose provenance. |
| DML-A03 · Profiling assumptions | Fused prefill buffers retained 1.5× logical K/V, context prompts could undershoot, asynchronous timing misrepresented TTFT, and peak reset could discard earlier repeats. FP32 weights under BF16 autocast later exposed mismatched KV estimates. | Preserve exact token lengths, synchronize timing, aggregate allocator peaks and report weight/KV dtypes separately. CUDA smoke passed on the 5080. Fused backing storage and decode concatenation remain part of the architecture's cost. |
| DML-A04 · Comparison validity | Tinyshakespeare, one configured seed and modeled FLOP equality could not support the memory/capability hypothesis. | Use B02/B08 controls, paired seeds, disjoint segments and full-split NLL on a versioned document corpus. Formal pilot remains pending. |
| DML-A05 · Load trust and broken untied head | Resume state is pickle-backed. Missing untied head weights originally fell through to random initialization. | Missing untied heads now fail. Treat optimizer/RNG checkpoints as trusted inputs. |
| DML-A06 · Artifact races | Refused resumes could move backups, contend for the same experiment or overwrite status. | Training validates in place, uses a cooperative lock and retains it through final status. Damaged backup and held-lock CLI cases were rechecked. Hard kills can leave stale locks. Reader tools and registry allocation need separate concurrency consideration. |
| DML-A07 · Evaluation limits | Fixed sampled validation windows overlap. Multiple-choice context and response tokenization can alter boundaries relative to joint encoding. | Full-split evaluator added for the pilot. Existing multiple-choice comparability remains a separate issue. |
| DML-A08 · Validation and reproducibility | Loose constructor/config and dependency assumptions weakened reproducibility. | Recurrence depth rejects booleans. Use immutable sources and pinned environments for counting runs. |
| Packed-data tampering or drift | A same-size packed-file edit could pass unchanged manifest validation. | Resume checks actual packed-file hashes and counts. Older checkpoint provenance produces a warning rather than proof. |
| Torn optimizer update | Injecting Ctrl+C after AdamW step 3 produced a rescue checkpoint labelled step 2. | Avoid rescue saves when a weight/optimizer update may be torn. Resume from the last committed state. Injection and resumed-trajectory checks passed on CPU. |
| Nonfinite completion | Injected NaN ran to completion and produced a checkpoint. | Loss/gradient/validation checks gate commits and record failures. Added pilot divergence and resource stop policies. |
| Changed trajectory on resume | A different batch size and clip under the same run ID changed tokens per update. | Check trajectory settings, allow explicit schedule extension only as a recorded deviation. |
| Replayed metric rows | Resume appended steps 3 and 4 again after a failed save. | Preserve raw rows and reconcile via attempt start steps. Test coverage compares interrupted/resumed and uninterrupted trajectories. |

The original controller, distinct recurrence schedules, and checkpoint hardening were evaluated in bounded smoke or failure-injection tests. A reported synthetic memory advantage does not reverse any of these historical findings. Future corrections should cite the specific record and the new evidence.

## Protocol and preserved TinyStories evidence

- The first 200-step training calibration and the corrected deterministic version remain separate records. The CUDA trajectory drift and same-stack exact recovery retain their original evidence. [Calibration comparison](../experiments/TINYSTORIES-CALIBRATION-ANALYSIS.md) · [Recovery incident and controls](CUDA-RESUME-INCIDENT.md)
- In the completed single-seed extended campaign each arm processed **100,007,936 training targets**. Full validation NLL was **1.718544** for B02, **1.518051** for B08, and **1.661239** for R02×4. Against B08, recurrence saved **18.0%** peak allocated training memory and increased median synchronized training throughput by **9.7%**. It recovered **28.6%** of B08's NLL improvement over B02. This evidence is scoped to the paired seed, TinyStories validation split and measured training setup. 27B-class capabilities and the inference hardware targets remain open.
