# Failure and correctness history

This supplement preserves the [original ledger](ledger.md). Detection and regressions refer to the source/audit artifacts in [CPU-AUDITS](../experiments/CPU-AUDITS.md). The corresponding [post-audit engineering notes](https://github.com/CL-BAF/Domovoi-Labs/blob/d914684dc730cd32132aeff389d6291c447ed7e4/POST_AUDIT_FIXES.txt) preserve earlier repro details. Each row is scoped to the checked case.

| ID | Detection and reproducible failure | Root cause / impact | Correction, regression and remaining limit |
|---|---|---|---|
| DML-A01 · Schedule drift | Save depth-2 cycle weights and attempt a same-shape depth-3 sequence load, or load as a baseline. Original logits shifted by 0.177509 in the audited comparison. | Tensor shape compatibility does not imply the same computation graph. A changed schedule silently changed the experiment. | `training/checkpoint.py` and `models/signature.py` compare stored graph and config before load. See signature and incompatible Config tests in `test_post_audit.py`. Files without explicit legacy signatures have weaker source provenance. |
| DML-A02 · Malformed caches and causal parity | Construct wrong-count, mixed-hole, mismatched slot-length, device, batch or geometry caches. Original audit recorded a 0.00435843 max logit shift on a wrong slot length. Compare full causal forward with prefill, singleton and chunked extensions; change unseen future tokens. | Structurally plausible cache lists could enter an incorrect execution history. An offset mask or wrong position start would break causality. | `models/kv_cache.py` and the active model track slot count, shapes/prefix and originating schedule when representable. `test_masking.py`, `test_recurrent.py` and `test_post_audit.py` cover future independence, greedy decoding and malformed inputs. CPU FP64 parity error was 2.22e−16. Plain list provenance and untested kernels remain bounded. |
| DML-A03 · Profiling and async time | Inspect uncached prefill backing storage, profile exact token IDs, inject an early large allocation into repeated runs, and autocast BF16 with FP32 weights. Old measurement paths could time launch rather than execution, underfill input or reset away earlier peaks. | Distinct underlying storage, cache dtype and asynchronous kernels invalidated ambiguous memory/timing claims. | `inference/generate.py` synchronizes, reports separate dtypes and uses exact counts; `profiling/profiler.py` aggregates timed windows and global peaks. GPU smoke regression passed. Fused QKV backing can still be 1.5× logical prefill K/V. Device-wide snapshot is not overall instantaneous peak. |
| DML-A04 · Invalid comparison inference | Compare first-run throughput from sequential random-ID GPU runs; reverse arm order. The leading arm on each fresh process had a slow opening window. | Setup/warm effects confound whole-run comparisons. Synthetic loss, one seed and modeled FLOPs cannot characterize real quality. | Maintain recordings and exclude a fixed initial window from medians. Fresh calibration pairs real data/geometry and synchronizes correctly. Missing profiler decomposition and paired-seed uncertainty remain. [Synthetic records](../experiments/RTX5080-BF16-SMOKE-001.md) |
| DML-A05 · Untied head and pickle boundary | Remove output weight from an untied checkpoint and attempt a load. Separately inspect optimizer and RNG readers. | Loose missing-key load could leave random output weights. Pickle-backed optimizer/RNG files must be trusted because deserialization is code-capable. | `_check_loaded_keys` permits only the expected tied alias. Regression rejects missing untied head. No general trust claim follows from checksum integrity. |
| DML-A06 · Partial save, refused preflight, races | Simulate damaged backup, stale/missing index, multiple run writers and refused resume. Original paths could recover/move incompatible backups or affect status before validation. | Non-atomic or unordered state mutation can create invalid/inconsistent restore points. | `CheckpointManager` staged writes and atomic latest replacement, trainer read-only preflight, post-load backup rename, held lock through completion and validated SHA-256. `test_rereview.py` and `test_round3.py`. Hard kills can leave stale lock/temp; incomplete index can still fail closed. |
| DML-A07 · Evaluation scope | Contrast overlapping fixed-window validation with document-boundary full scoring; test mixed files and mask padding. | Partial windows and cross-document targets change the measurement. Some multiple-choice tokenization has separate context/continuation boundary risk. | `evals/full_split_nll.py` sums valid targets over document windows and validates source hashes. `test_pilot.py` covers exact count and partial scores. Broad task adapters have not been benchmarked here. |
| DML-A08 · Recurrence validation and reproducibility | Try bool/noninteger depth, unavailable dtype or a claim using an unpinned working tree. | Invalid settings or incomplete source provenance can compromise reproducibility. | Validate recurrence/dependencies and record exact revisions before counting runs. The first synthetic run's source commit is unavailable and cannot be reconstructed from a later digest alone. |
| DML-R03-DATA · Packed drift | Modify a packed file while preserving length and its old manifest. | Metadata-only checks missed changed actual next-token inputs. | Trainer hashes actual opened files and compares data/tokenizer identity. `test_round3.py` rejects same-size changed bytes; old metadata can produce weaker validation warnings. |
| DML-R04-TORN · In-update interrupt | Inject Ctrl+C after AdamW update 3 but before clean-step commit. Original rescue claimed step 2 with step-3 AdamW counters. | Replaying would apply a batch to weights that had already processed it. | Use the last committed checkpoint when an update mutates state. `test_round4.py` injects optimizer interruption and checks replay. The tested CUDA exact control is a separate clean-boundary test. |
| DML-R04-NAN · Invalid numerics | Inject NaN train/validation loss or force nonfinite gradients. Original path recorded COMPLETED and saved a bad checkpoint. | Failure modes could look successful in metadata. | Check before updating on invalid loss/grad or before publishing a checkpoint on invalid validation. Record FAILED and cause. Regression tests exercise injected cases. Unsupported or unstable configurations still need gates. |
| DML-R04-PROTOCOL · Changed trajectory | Resume with other batch, clip, LR/schedule, seed or sampler. | Restart could silently change experiment conditions. | Strict trajectory comparison and recorded extension deviation. `test_round4.py` varies all tracked fields and permits only explicit bypasses. Cross-driver repeatability remains untested. |
| DML-R04-LOG · Duplicated rows | Fail after logging later updates, roll back to older checkpoint and append replayed rows. | Treating duplicate attempts as one timeline biases analysis. | Keep append-only raw files with attempt starts, reconcile downstream. Resume and forced failure tests compare histories and weights. |
| DML-DATA-JOURNAL · Multiworker tokenizer failure | Tokenizer iteration over production-size SQLite corpus raised a thread-affinity exception. | A Rust worker consumed a generator tied to another thread. No prepared directory should be published at failure. | Write bounded train-only file sample, then call the tokenizer on that file. Rerun the unchanged spec to recover ingestion journal. `test_streaming.py` exercises interruption and deterministic outputs; the original stderr is not fully archived. |
| DML-CUDA-001 · Nondeterministic default trajectory | Checkpoint tensors exact, final default-CUDA vs uninterrupted diff **0.001584119**. | Divergence begins before restore, compatible with nondeterministic kernels. Operation responsible not established. | Deterministic algorithms, workspace env, checked config and artifact SHA-256. Same-stack repeat diff **0.0**. [Standalone incident](CUDA-RESUME-INCIDENT.md) |

For every fix, multiple tools can detect separate failure scopes. E.g., successful file checksums verify bytes, correct RNG restore verifies state, and CUDA trajectory equality verifies repeatability only within the bounded controlled workload. The resource and quality hypotheses are maintained in a separate [structured findings ledger](architecture-hypotheses.md).
