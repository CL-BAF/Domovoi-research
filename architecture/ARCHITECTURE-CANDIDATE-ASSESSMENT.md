# Ranked architecture candidate assessment

The order is a draft research priority. C0 is mandatory and runs alongside the first C2 study. Rank changes require a new finding with an equal-resource control. Candidate memory projections are accounting scenarios. No candidate has measured parity, 8K qualification, or a 4 GiB deployment run.

## C0 · Mandatory native scalar low-bit control

**Question and mechanism.** How much of the objective comes from a strong conventional design and appropriate training? Use a fixed-depth causal transformer or mature hybrid. Train scalar quantizers from initialization with `w = s × round_clip(u/s)`, or ternary weights plus scale, and make the packed representation canonical. The smallest causal comparison uses the same transformer and floating-point embeddings/attention for all arms while isolating coded feed-forward weights.

**Prior art and size.** Scalar QAT, BitNet, Spectra, GQA and Gated DeltaNet are established. With INT4 group-64 FP16 scales the effective rate is 4.25 bits for those weights before alignment. At 3,380 MiB it fits about 6.67B weight slots if every byte can be assigned to that uniform representation. A practical model uses fewer slots because of uncompressed tensors, indexes, state and runtime. A ternary arm has representational and optimizer risk plus kernel dependencies. Mature scalar kernels give a high bar for bandwidth and speed. Distilled variants have a separate teacher/no-teacher comparison.

**Falsifier and role.** C0's implementation fails as a control if deployed logits fail parity, the scalar code is insufficiently tuned, or measured metadata is missing. Its empirical frontier is the null. C0 can improve bytes and deployment as a baseline, and any broad capability shortfall remains a fact about that setup. There is no new mechanism claim. [BitNet report](https://arxiv.org/abs/2504.12285) · [Precision scaling](https://arxiv.org/abs/2411.04330)

## 1 · C2 native learned vector codes

**Question and mechanism.** Does a learned discrete representation retain more reliably retrievable information per resident byte? Partition weights into size-`g` vectors, `w_j = s_j Σ_m C_m[i_jm]`. With two 8-bit indices per eight weights and one FP16 scale per 64 weights, the ideal rate is 2.25 bits/weight before shared books, dimensions, tiles, or mixed precision. Shared dictionary transforms or per-layer bit allocation are later variations. Train with hard codes in the forward pass from initialization and count search, surrogate gradients, scale updates and deployed reconstruction.

**Potential benefit.** At 2.25 vs 4.25 bits, the coded portion could store about 1.89× as many matrix entries for the same bytes. This does not establish equivalent effective parameters or any retained factual gain. The plausible contribution is a measured improvement in learned information density and possibly joint allocation/reconstruction matched to device traffic. C2 does not change sequence-state asymptotics. Native VQ feasibility on Ampere is open. Nearest comparisons include strong rate-matched scalar, fixed vector codes, AQLM/QTIP in the separate PTQ track and LC-QAT/MXCode for related training and inference mechanisms.

**Failure tests.** Codes can collapse or forget rare facts. A larger logical matrix can cost more FLOPs, attention plumbing and memory expansion, and code decoding may erase the bandwidth benefit. VQ should improve both an equal-byte frontier and the learned-versus-fixed ablation at the same rate. Match compute in an independent window. Stop deployment work if the learned advantage disappears, does not transfer to natural held-out text, or needs a resident dequantized duplicate. Strong correct evidence here could help factual and general competence, conditional on scale. [First study](../experiments/proposals/C0-C2-DEPLOYED-BYTE-STUDY.md) · [AQLM](https://arxiv.org/abs/2401.06118) · [LC-QAT](https://arxiv.org/abs/2606.10531v3) · [MXCode](https://arxiv.org/abs/2611.00403v2)

## 2 · C1 resident associative store and a small looped core

**Question and mechanism.** Can the model carry many learned associations while applying extra reasoning without rereading all its bytes? At latent step `k`, read `m_k = Σ_{i in topK(q_k)} p_i V_i`, then `h_{k+1}=F(h_k, h_0, m_k)`. Put sequence mixers before/after the shared core. Keep tables, keys, cache and all parameters resident. Product-key routing narrows candidate search. Count top-k, irregular fetches, core/embedding reads and the dependency chain.

**Potential benefit.** A modeled 0.31 GB of fixed matrix reads plus about 0.62 GB per core pass in the independent C1 example creates room for several loops where a 3.54 GB full stream allows about three under its hypothetical 2050 roofline. The original 16-pass estimate omits or idealizes material traffic such as the output head, state and lookup misses. Memory values cost their bytes even if unused. This primarily shifts reasoning work per byte read. Whether stored facts beat a dense representation is unknown.

**Prior art, originality and falsifier.** PKM, Engram, PEER, end-to-end memory networks and Ouro validate ingredients. Testing a joint allocated-byte/traffic frontier with causal per-loop retrieval could be an original result. Require a five-point composition gain over both same-budget ablations, advantage over a single query, comparable natural NLL and measured speed with no host service. Cold/rare lookups, routing collapse and serial latency can dominate. Promote C1 only when it removes a measured bottleneck. [Engram](https://arxiv.org/abs/2601.07372) · [PKM](https://arxiv.org/abs/1907.05242) · [Ouro](https://arxiv.org/abs/2510.25741v6)

## 3 · Selective state and sparse exact attention

**Question and mechanism.** Can a bounded causal state retain context quality at substantially lower context memory? Update `S_t=A(x_t)S_{t-1}+B(x_t)x_t^T`, with a readout and a small number of GQA blocks holding exact local/global signals. Constant state across context for selective layers and a window `W` constrain their storage. A 16-block BF16 `1024 × 64` state is 2 MiB, and four 512-token BF16 GQA layers in the earlier example add 4 MiB of logical KV. Full deployment bytes can be far higher.

**Prior art and bar.** Mamba-2, Gated DeltaNet and Gemma local/global GQA cover the basic mechanisms. A learned allocation might be distinct if it wins against both fixed hybrid and all-attention controls with matched weights/compute. Use predefined 2K and 8K diagnostics including exact rare lookups and multi-hop binding. Require the earlier proposed ≥5-point multi-hop improvement over state-only and within 0.05 nats/target of full attention at 2K, plus an actual state/latency win. Defer as the primary direction because the verified Qwen reference already combines learned recurrent state and GQA. It is a useful control or remedy for a measured context bottleneck. [Mamba-2](https://arxiv.org/abs/2405.21060) · [Gated DeltaNet](https://arxiv.org/abs/2412.06464) · [Gemma 3](https://arxiv.org/abs/2503.19786)

## 4 · Adaptive computation and latent cache

A causal gate chooses application count from token-visible state. A read-only token latent `z_t` can reconstruct `K_t=W_K z_t, V_t=W_V z_t` when needed. The earlier proposal derived 32 MiB versus 256 MiB logical history at 8K for 16 layers and a 128-wide BF16 latent versus full BF16 KV. This excludes extra projections and any persistent expanded cache. An average of 1.5 vs two passes offers at most 25% fewer applications before overhead. MoD and MoR establish routing prior art; the open contribution is co-design of causal retrieval representation plus task-adaptive compute. Require decode/prefill parity, better results than equal-budget random routing, and ≥10% actual steady decode gain with a tail cap. Poor batch-1 scheduling and activation expansion can cancel everything. Can improve speed or reasoning under measured bottlenecks. Stored knowledge need not change. [MoD](https://arxiv.org/abs/2404.02258) · [MoR](https://arxiv.org/abs/2507.10524)

## 5 · Learned consolidation

Bound capacity with an exact recent buffer and `M_{t+1}=Write(M_t,x_t;gate_t)` over a fixed set of slots. With the earlier 256+128 position example, 16 layers, four 128-wide KV heads and BF16, logical storage is 12 MiB. The idea targets context quality per byte, not permanent factual density. Titans and ATLAS cover learned updates. A useful contribution would be selective exact retention with a stable read latency and better natural delayed evidence than uniform pooling. Against recency-only, pooling and a same-budget exact store, require ≥5 points of 8K multi-hop gain and ≤2 points of short-context loss. Protect against shortcut queries, attention to hidden labels and erased rare facts. [Titans](https://arxiv.org/abs/2501.00663) · [ATLAS](https://arxiv.org/abs/2505.23735)

## 6 · C3 modular programs and procedural state

The independent proposal routes low-rank adapters `W + Σ_i α_i A_i B_iᵀ` at each latent step. The earlier typed-register design instead uses bounded operations over scratch slots. A 64-by-512 BF16 scratch register is 64 KiB while 16,384 rank-8 adapters of the proposed shapes add 1,280 MiB of raw INT4 weights before scales. Router and whole library still count. Neural Module Networks, NPI, DreamCoder, dynamic LoRA composition and MoE are direct prior art. A genuinely selective, learned internal operation that transfers to unseen compositions would be useful. Demonstrate ≥10 points of held-out composition gain for the typed variant over dense and untyped recurrent controls, ≤2 points of in-distribution loss, selective lesion of relevant operations, and a hard latency budget. Static modularity or an external script library has little evidential value for across-task capability. Keep deferred unless C1 exposes a composition bottleneck. [Modular networks](https://arxiv.org/abs/1511.02799) · [LoraHub](https://arxiv.org/abs/2307.13269) · [DreamCoder](https://arxiv.org/abs/2006.08381) · [Modularity study](https://arxiv.org/abs/2206.02713)

## Ranking sensitivity

Once real measurements exist, promote the alternative that clears its own control at equal total memory and matched task conditions. A missing fast code kernel favors C0 or a hardware-supported coded variant. A clear multi-hop benefit at unchanged factual density favors C1. A candidate that saturates context storage before weights can reach a useful operating point justifies early context work. Native learned codes, state-space allocation and routing all draw on established mechanisms. A new result must specify which joint design or measured frontier is new.
