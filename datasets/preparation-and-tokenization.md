## Evidence and data lineage

The raw files stayed on the NAS. The Windows process read them over SMB and wrote the SQLite staging store, packed uint16 binaries and checkpoints to local NVMe. The portable specifications replace the original mount and user paths with roots that can be set by another operator. No raw text or bulk token files are published here. The file inventories distinguish source revisions, sizes, upstream download metadata, actual SHA-256 and decoded records. The original inventory was generated on 24 November. During publication the Windows SMB mapping was disconnected and both mount paths failed read access. The initial inventory's 20 successful source hash checks remain on record. The publication verified the locally retained packed/tokenizer bytes again, and did not complete a second read of raw NAS bytes.

## Streaming path

`scripts/audit_corpora.py` checks expected paths, temporary suffixes, bytes, SHA-256 and cached upstream revision. UTF-8 decoding is strict. PyArrow validates arrays in every decoded text row group and supports Parquet page checksum verification where available. The source check covers the text column rather than all payload columns. Its counters include null and whitespace-only values. Match against the [machine-readable inventory](data/NAS-INVENTORY-2026-11-24.json).

`prepare_streaming` validates the full SHA-256 of each selected raw source before ingestion. Text blocks of 64 Ki characters retain the incomplete delimiter fragment across reads. Parquet batches select a configurable string column. Readers impose document size bounds. The SQLite journal records source number, decoded position and filtering counters, committing in batches. On retry the same pinned specification is required; the source reader replays up to the journal position. A separate packing journal records last document row, bytes in token/offset streams and document counts. The packer flushes bytes before committing the journal and truncates any uncommitted tail when resumed. A staging writer lock protects concurrent writers, and the final prepared directory appears through a rename when complete. Hard-killed lock owners require an operator check before removing the lock. SQLite staging databases may contain licensed text and stay local.

Normalization is Unicode NFKC, case folding, then whitespace collapse, used to compute a deduplication SHA-256. Original stripped text proceeds to tokenization. Existing held-out splits take precedence during exact deduplication. For hash-split files, an integer derived from the first eight digest bytes modulo 1000 chooses the split, preserving consistent assignment for duplicates. Hash deduplication is exact only. Block-level training segments may cross document boundaries with EOS; evaluation never scores a cross-document target. Future mixtures have deterministic first-eligible document quotas by source ID, recorded proportions and a seeded segment permutation. Document weights do not equal token weights for unequal document lengths. The published training runs use single-source data.

## Tokenizer and binary contract

The current tokenizer's byte-level BPE consumes a bounded train-only sample, default 16 MiB, written as local text before training. The decoder corresponds to the byte-level pre-tokenizer, no prefix space is added, and Unicode round trips are tested. The vocabulary target is 4096 including EOS, with actual vocabulary checked against model config. The publishing scripts verify tokenizer hashes, split lengths and raw packed bytes. One exact TinyStories tokenizer is shared by all six calibration runs and all three extended arms.

Encoding works in bounded batches of 512 documents. One EOS token is appended per document. Packed shards store little-endian uint16 IDs. Sidecars contain exclusive cumulative document ends as JSON integers. Each final offset must equal its packed token count. EOS occurs at each recorded end, and IDs must be within vocabulary. Their input names, file sizes and cryptographic digests are in [the bulk artifact manifest](../provenance/artifact-hashes/2026-11-24-local.json). At these vocabularies uint16 is sufficient. Larger than 65,536 IDs would require a new format and loader. Intermediate SQLite and tokenizer samples are neither training-ready artifacts nor public sources.

A production-size preparation attempt failed when the Rust tokenizer iterator moved a SQLite connection between threads. It did not publish an incomplete ready directory. A spool file created with bounded train-only data removed the thread affinity dependency. Reusing the same spec resumed from the intact journal and the ready artifact checks completed. The small CPU suite tests invalid UTF-8, wrong schema and checksum, split deduplication, vocabulary/round trip, journal interruption, packing hashes, deterministic corpus reproduction, and mixture quotas. See [failure chronology](../findings/failures-and-corrections.md).
