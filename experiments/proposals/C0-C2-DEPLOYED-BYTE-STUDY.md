## Question and hypothesis

Can a natively trained vector-coded network retrieve more independent, random facts per byte of its actual deployed representation than the strongest native scalar model? Separate capacity from memorization at finite exposures and measure storage, precision, training compute and inference cost independently.

For a world with identity $i$, attribute $a$, and two uniformly sampled value bytes $Y$, let $X$ be its query and $q_\theta$ the model's conditional probability over allowed values. For a frozen paired test set, estimate extracted information $K = N_f[16 + \operatorname{mean}(\log_2 q_\theta(Y\mid X))]$ bits, with $N_f$ independent facts. Log probabilities factor by byte under teacher forcing and are normalized on the same 256 allowed byte tokens at each step. This estimates a population lower bound for information usable by this predictor under a uniform reference. The sample estimate has uncertainty. Negative estimates remain visible. Also record unrestricted generated two-byte exact match, invalid output rate, and calibration. Distinct test prompts share labels for trained identities, so inference statistics cluster by identity.

The primary density is $D=K/(8 B_{\mathrm{resident}})$. $B_{\mathrm{resident}}$ is the sum of actual on-device representation allocations including scales, indices, codebooks, padding, fixed tensors and duplicated persistent representations. Record $K/(8 B_{\mathrm{peak}})$ and absolute post-load and prefill/decode peaks separately. This distinction prevents a device context floor from swamping a small-model weight study while still exposing deployment failures. A packed checkpoint size is a diagnostic. The comparison requires an executable backend and logits parity through the compact path.

The predeclared effect question is whether, at high load and 100 exposures, learned C2 achieves both **≥1.20× density of every scalar control** and **≥1.30× density of INT8** after matching resident bytes within 3%. At identical width and byte format it must also improve on fixed VQ by **≥10%**. Treat estimates below 5% of world entropy as weak ratio denominators. Require BF16 and INT8 to exceed this floor on all high-load worlds. For smaller control values report absolute $K$ deltas, identity-cluster intervals and the floor violation. An invalid key comparator blocks the advancement rule.

## Data and leakage controls

- Generate 65,536 trained identities with four attributes per identity. Each answer has two independent uniform bytes. The world's exact entropy is **4,194,304 bits** for 262,144 independent facts. Use a second smaller 16,384-identity world to test the instrument, at 20 exposures. Use the full identity space with uniformly random labels so the entropy ceiling is not a trivial limiting factor in the main screen.
- One training example is seven positions, with `BOS, ID_hi, ID_lo, attribute, value_hi, value_lo, EOS`. Only the two value positions contribute supervised loss. Batch 4,096 queries/update using 256-query microbatches with accumulation of 16. Use block-independent causal attention across packed examples, context at most 16 for held-out query forms, and pad/measure separately if a kernel requires it. The compute model below counts seven positions per training example even when an implementation skips an unused position. Record label-bearing and processed positions separately.
- At 20 and 100 exposures of every trained fact, the main dataset processes 36,700,160 and **183,500,800 positions**, and scores 10,485,760 and **52,428,800 value targets**. The low-load diagnostic uses 9,175,040 positions. No read of the natural transfer test or public benchmarks occurs during this experiment.
- Pair initialization seeds `1234, 1235, 1236` with separately domain-derived dataset, order and holdout keys. Generate independent worlds across seeds, paired examples and order across arms. Precommit SHA-256 digests for the generator code, seed derivation, split and fixtures. Keep the generator secret and raw holdout answers outside the model runtime and inaccessible to tokenizer construction. Learned codebook entries may depend on the same training examples as other learned weights. Once archived, seed receipts must make the experiment reproducible. Never use an identity/label hash formula as side information at inference.
- Use a fixed 512-entry token alphabet for every arm. Tokenization and attribute names are label-independent. Leave out defined alternative query templates from training and use label-free snippets to check their representability. Canonical prompts measure direct retrieval and held-out order/format prompts diagnose transfer with no answer-bearing context. Use a separately drawn untrained namespace tagged by a fixed token and held-out facts for the negative control. Include uniform predictor, independently permuted labels, and an oracle (harness only) to detect leakage or estimator saturation. Cluster prompt variants by identity in uncertainty intervals. Training identities may recur in retrieval probes because stored knowledge is the object of study. Novel associations and query generalization are separate.

## Backbone and controls

Use a four-layer causal transformer with `d=64`, four attention heads, causal RoPE, RMSNorm, bias-free GELU MLP with two matrices, and a tied BF16 embedding/output head. The two RMSNorms per block and output norm are BF16. Embeddings, attention projections and norms remain BF16. Those fixed tensors contain **98,880 values and 197,760 bytes**. Only the MLP matrices change representation. Their count is (P_f=512 f) for intermediate width (f). Use the same activation precision and train all low-bit arms from the first forward pass without a teacher or a pretrained proxy.

| Arm | Proposed representation | Matched-byte (f) | Planned GPU payload bytes |
|---|---|---:|---:|
| BF16 instrument and geometry control | BF16 FFN | 320 | 525,440 |
| Native INT8 | group-64 symmetric signed scalar code with FP16 scale | 640 | 535,680 |
| Native INT4 | group-64 symmetric signed scalar code with FP16 scale | 1,216 | 528,512 |
| Native ternary | {-1,0,1}, two-bit random-access indices and FP16 group-64 scale | 2,368 | 538,752 |
| Native scalar 2b | four symmetric levels {-3,-1,1,3}, FP16 group-64 scale | 2,368 | 538,752 |
| Fixed VQ2 | two unsigned-byte code indices per eight FFN values, shared fixed BF16 books and FP16 group scale | 2,304 | 537,728 |
| Learned VQ2 | same codes, payload and forward graph with trainable books | 2,304 | 537,728 |

The byte budget envelope is 528 KiB before engine allocations, with payable scales and fixed books included. All widths are multiples of 64. The VQ rows count two 256 × 8 BF16 tables (8,192 bytes), two indices per eight values, and one FP16 scale per group of 64. Index rounding, tile padding, allocation granularity and copies must be measured in the deployed engine. Before approval, use exact backend layout to freeze widths and a ≥3%-control-mismatch rule that invalidates the comparison. If any under-cap model is >3% from the group envelope, lower the shared budget or adjust widths without looking at task outcomes. BF16 values are canonical for fixed full-precision tensors. A backend which expands complete FFNs into BF16 for all decode steps is a separate diagnostic and fails the compact deployment condition.

The additive code for normalized vector (u) is (c_1[j_1]+c_2[j_2]). Choose (j_1) by nearest code, then (j_2) by nearest residual with deterministic index tie-breaks. Initialize both variants identically using deterministic orthogonally rotated eight-dimensional hypercube tables, with second-stage initial scale one-half. Publish transformations, order and indices in the future plan. The fixed table remains frozen and charged to storage. The learned variant trains codewords through gathered values and a straight-through proxy for assignments, with the same scales and BF16 deployed computation. Refresh hard codes once per optimizer update using blockwise search with ≤2,048 vectors and 256 codewords per tile. Count ties, occupied codes, commit checks and reconstruction residual per layer. QAT arms use matched learned positive group scales and STE for proxy gradients. Precision changes and optimizer support must be validated by a separately reviewed deterministic correctness fixture before inference evidence.

Use a common starting recipe of AdamW with `beta=(0.9,0.95)`, peak learning rate `3e-4`, weight decay `0.01` on dense proxies, 2% warmup and cosine decay to 0.1 peak at the prescribed horizon, gradient norm cap 1.0, no dropout, no teacher. Match training schedule to the block horizon, expose codebook learning-rate and clipping policy, and freeze them before using result-bearing worlds. Allow equal prespecified tuning on a disjoint calibration world or none for every arm. Report tuning trial counts and compute. Keep fixed versus learned VQ optimization outside the codebook identical. Publish raw nonfinite or collapsed runs, and follow the protocol before any retry that changes settings.

## Budgeted contrasts and interpretation

| Block | Comparisons and fixed quantities | Inference allowed by a contrast |
|---|---|---|
| Instrument | BF16 and INT8 at fixed width 320, low-load world, 20 exposures, three paired seeds. Uniform/permuted/oracle checks. | Establish scorer calibration, masking, data entropy, exact pack parity and negative-control null. A trivial underloaded instrument is not evidence of a capacity ceiling. |
| A · Equal geometry and tokens | All seven arms at width 320 on the high-load world, three seeds, 20/100 exposure checkpoints. | Isolate representation at equal architecture, unique logical slots and data exposures. FLOPs for code search and kernels differ and are reported. |
| B · Equal resident bytes and tokens | Matched-width table above. Reuse the identical BF16 run from A. Three paired seeds with identical exposure schedule. | Test the practical density frontier. More width can consume more compute. Fixed/learned VQ remains a clean same-geometry ablation. |
| C · Matched modeled training compute | Use INT4, scalar 2b, fixed VQ and learned VQ at B widths with independent endpoint schedules under the BF16 100-exposure model-compute budget. Reuse the BF16 A end point. | Compare capable output under a common analytical compute cap. Exposure counts differ by design. Publish actual time, bytes, operators, search overhead and data order prefix. Do not infer matched hardware cycles from the analytical FLOPs. |

Expected ranges are deliberately conditional. The literature's 1–2 bits/parameter at different exposures is from a different model/data regime and gives no hard instrument target. Applied to 262,720 BF16 logical values as a scenario it would correspond to roughly 0.0625–0.125 extracted bits per raw stored bit. For the same shape under low-bit encoding, divided density can rise even if total information falls. The uniform baseline is (D=0) and oracle (K=4,194,304) in the high-load main world. A fully saturated probe, near-zero C0 or positive null calls for a new reviewed instrument or load bracket, with no claim for or against C2.

## Compute, resources and stopping

- The budget uses $F_{\mathrm{token}} \approx 6(P_0 + P_f) +12 L d T_{\mathrm{seg}}$ with $T_{\mathrm{seg}}=7$, counting the output projection, conservative attention score/value work and forward/backward matmuls. Two residual searches with 256 choices add approximately $1{,}024 P_f$ FLOPs/update for VQ if norm/dot reuse holds. Log gather, packing, scale and optimizer operations. At 28,672 processed positions per full update, the matched-compute ceiling in C permits about 2,350 INT4, 1,296 scalar 2b and 1,322 VQ updates. Verify exact op/step accounting before pinning. Compare full steps under the same frozen FLOP ceiling.
- The upper schedule is (6 + 21 + 18 + 12 = 57) model-seed runs, including instrument and reused controls, approximately **30.8 PFLOP** of modeled training operations. Under assumed effective rates of **0.5–5 TFLOP/s** this is about **17.1 to 1.7 GPU-hours** of idealized workload time. No rate in this range has been measured for this design. Host scheduling, tiny GEMMs, assignment, synchronization and decoding may extend wall time. Use **18 GPU-hours total** and **12 GiB training allocated** as proposed hard limits, **20 GiB local scratch** for checkpoints/logs, and reserve only the planned number of checkpoints and diagnostics. Publish partial work on an overrun. Do not convert TinyStories' 58 TFLOP/s model estimate into this plan's throughput.
- The RTX 5080 is the development device for this screen. Use deterministic BF16 training, an explicitly versioned CUDA and driver stack, and a verified GPU packed decoder. The first approval should include codec and config digests for all variants, GPU environment, exact runner command and parity limits. Qualification on an RTX 2050, a teacher run, and large-model comparisons are separately planned.

## Success, failure and next decision

1. **Stop after the instrument block** if the oracle/negative tests fail, compact path produces differing decoded weights/logits outside a frozen dtype tolerance, or a budget/metadata alarm occurs. Publish the failure before a new plan. Check whether the recovered information curve has headroom at early and late exposure. If every high-load arm is near the entropy ceiling or C0 is near zero, this test cannot separate densities.
2. **Advance to a separate natural-data study** only if the primary density margins hold in all three paired seeds at 100 exposures, the learned ablation holds against fixed VQ, the early-exposure direction is consistent, and the compute-matched learned density is within 5% of or exceeds the best scalar C result. Report descriptive paired per-seed differences, paired identity-block intervals and seed dispersion. Three seeds are a screen, not a robust 95% population conclusion. Use an eight-seed confirmation and a second size/load prior to a scaling claim. Compare multiple scalar controls simultaneously or report the maximum by paired bootstrap with all raw comparisons.
3. **Drop the learned-code hypothesis** for this design if it loses to rate-matched scalar, ties fixed vectors, or needs a slower path with a full expanded copy. If it merely wins on equal bytes and needs markedly more training compute, publish the Pareto frontier as a width/compute trade. If a higher-rate conventional C0 dominates, move that control forward and retire this C2 instance. If fixed VQ wins, study the fixed representation separately.
4. **Reject broad claims** if random-fact gains fail to transfer to held-out query forms, natural text NLL or controlled composition. A narrow capacity improvement can stand alone. A higher rate at short contexts is not evidence for 8K or target-card throughput.
5. For the **next planned transfer**, compare the best native scalar and any surviving coded model on a shared tokenizer and versioned natural corpus with doc-level decontamination and a sealed test split. Start at 20M processed language tokens per arm and extend to 100M only if predeclared quality and kernel gates clear. Add clean long-tail recall, natural paired prompts and exact-answer multi-hop diagnostics. Separate compute- and byte-matched runs with frozen schedule endpoints. Reject improvements that vanish on natural text or require unsafe extrapolation of 5080 bandwidth to the physical 4 GiB device.
